# Code Generator
Code generator is an automation tool that is able to generate repetitive code sequences (e.g. definition of handle tasks in scheduler or macro definitions of GPIO pins of microcontroller) according to a defined recipes (or expressions).
<br>


## 1. Code generator expression
The code generator expression might consists of:
- constants - either system variable or word from a python dictionary (loaded from a JSON file)
- functions - for a detailed list and usage examples of all available functions of code generator visit [code_generator_functions.md](../../tools/python/code_generator/code_generator_functions.md)

In order to be evaluated, each code generator expression must be encapsulated in the angle brackets and dollar sign needs to be before the expression e.g. `<$expression>`

The code generator expression has to be written in a template file. A new file is created by code generator which interprets expressions in the template file.
<br>


## 2. User sections in the generated file
Generated file (and thus template file, too) might contain also user sections which allow user to add their code to auto-generated file. Code added by user to the user section is always preserved (contrary to placing user code to automatically generated section where it will be lost - replaced with generated code).

User sections have to be marked in the template file with following comments:
- `USER CODE BEGIN <identifier>` or `USER SECTION BEGIN <identifier>` - at the beginning of user section, _\<identifier\>_ of user section must be unique
- `USER CODE END [<identifier>]` or `USER SECTION END [<identifier>]` - at the end of user section, _\<identifier\>_ is optional

For example, see user section _ProjectModules_ in the template file [common/prog/schedulers_bm/scheduler/cfg_templates/scheduler_auto.h](../../prog/schedulers_bm/scheduler/cfg_templates/scheduler_auto.h):
```c
...
typedef enum SCH_ModuleIDs
{
<$foreach(var,$(scheduler_tasks),macro("    MOD_$1,/n",$(var.name)))>
    /* USER CODE BEGIN ProjectModules */
    /*! place your projects modules here */
    /* USER CODE END ProjectModules */

    TOTAL_MODULES
} TaskID;
...
```
<br>


## 3. Examples of Use

### 3.1 Creating code generator expression
Two variables, table `table_days` and list `my_list` are defined.
The variable `my_list` is sorted in the ascending order (by the function `sort()`) according to "days" value (number of the days). The macro is created for each item in `_my_list_` by using "name" value and respective "days" value of `my_list`'s item. However, by using the `table()` function a string representation of the corresponding "days" value is taken from the table `table_days` (the "days" value of each `my_list`'s item has to be converted from integer to string by `str()` function in order to be used as argument of `table()` function).
```c
<$define(my_list, [{"name":"Year", "days":365}, {"name":"Week", "days":7}, {"name":"Month", "days":30}])>
<$define(table_days,{"365":"three hundred sixty-five","30":"thirty","7":"seven"})>

<$foreach(item, sort(my_list, "days"), macro("$1 has $2 days.\n", item.name, table(table_days, str(item.days, 0, 4))))>
```
The output of code example looks like this:
<br>`Week has seven days.`
<br>`Month has thirty days.`
<br>`Year has three hundred sixty-five days.`
<br>

### 3.2 Generating a file by code generator
There are two ways available how to generate a file by code generator:
* using `gen_hdr` / `gen_src` make variable - with this approach a header or source C/C++ file will be generated (and in the case of source file it will also be compiled) automatically when rebuilding project application
* using `code_gen` make variable - with this approach a file with whatever file extension can be generated by calling respective make target `make <gen_file_name>`


#### 3.2.1 Generating a file using `gen_hdr` / `gen_src` make variable
1. Create a template file (file extension can be either `.h`, `.c` or `.cpp`) with a custom name, e.g. _example.h_ and place it into folder cfg_templates/ located in a folder where output file will be generated, e.g. _app/prog/demo_component/cfg_templates/example.h_ . Every folder in the project with the name "cfg_templates/" is automatically searched for template files of code generator.

2. Write down desired code generator expressions into the template file (for this see the code example above in the chapter **3.1 Creating code generator expression** or examples of using [code generator functions](../../tools/python/code_generator/code_generator_functions.md)).

3. Into any _.mak_ file that is included into build process (e.g. into _app/build/\<variant>.mak_) add a file that will be generated to the make variable either `gen_hdr` in case of header file or to `gen_src` in case of source file. The generated file must have the same name as the template file and if it's placed into some component, the path after the folder prog/ has to be written, too. E.g.:
   ```makefile
   gen_hdr += <gen_file_path>/<gen_file_name>.h
   ```
   In this example, it will look like this:
   ```makefile
   gen_hdr += demo_component/example.h
   ```

4. Rebuild project application. After that a new file (e.g. _app/prog/example.h_) shall be created from the template file with generated code inside. If source file is created, it will also be compiled.
Each time some change occurs in the template file, by rebuilding project application the output file is regenerated (previous content is overwritten) and in case of source file it is also compiled together with the project application.
<br>


#### 3.2.2 Generating a file using `code_gen` make variable
1. Create a template file (with whatever file extension) with custom name, e.g. _example.tpl.c_ and place it either in the project root or anywhere in the app/ folder, e.g. _app/prog/example.tpl.c_ .

2. Write down desired code generator expressions into the template file (for this, see code example above in the chapter **3.1 Creating code generator expression** or examples of using [code generator functions](../../tools/python/code_generator/code_generator_functions.md)).

3. Complete and put this code into any _.mak_ file that is included into build process, e.g. into _app/build/\<variant>.mak_ of application, e.g.:
   ```makefile
   code_gen += <gen_file_name>
   <gen_file_name>_template = <tpl_file_path>/<tpl_file_name>.<file_extension>
   <gen_file_name>_output   = <gen_file_path>/<gen_file_name>.<file_extension>
   ```
   In this example, it will look like this:
   ```makefile
   code_gen += example
   example_template = app/prog/example.tpl.c
   example_output   = app/prog/example.c
   ```

4. Call respective make target `make <gen_file_name>` (e.g. `make example`).
A new file (e.g. _app/prog/example.c_) shall be created with code generated within it.
Each time some change occurs in the template file, by calling make target `make <gen_file_name>` the output file is regenerated (previous content is overwritten).
<br>


### 3.3 Adding handle task of application to "old" scheduler by using configuration JSON file
1. Set automatic configuration of scheduler tasks by setting `scheduler_config = auto` into _common_config.mak_.

2. For each handle task, in the folder of respective application component create a configuration JSON file (e.g. _config.json_) with these items:
   ```json
   {
       "scheduler_tasks":[
           {
               "name":"SAL",                         // name of scheduler task
               "handle_function":"SAL_bHandleTask",  // name of handle task of app. component
               "include_file":"SAL/sal.h",           // name of include file of app. component
               "priority":"high",                    // priority- either high of low
               "dependency":"DEP_SAL"                // dependencies of SAL scheduler task
           }
       ]
   }
   ```
   As an example of configuration JSON file, see the definition of DBus or timer handle tasks in [dbus/config.json](../../prog/dbus/config.json) or [timer/config.json](../../prog/ped_fw/timer/config.json).

3. Add file name _config.json_ into `code_gen_cfg` make variable within the _build.mak_ file of respective application component:
<br>`code_gen_cfg += SAL/config.json`

4. Rebuild project application. After that application handle task will be added to scheduler with corresponding entries according to its configuration JSON file, see auto-generated scheduler files:
<br>_app/prog/ped_fw/schedule/\<variant>/schedDef_auto.h_
<br>_app/prog/ped_fw/schedule/\<variant>/schedDef_auto.c_

You can see the content of scheduler files generated according to this example also here: [schedDef_auto.h](schedDef_auto.h_example-SAL.md), [schedDef_auto.c](schedDef_auto.c_example-SAL.md).
